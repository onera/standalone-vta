# VTA baremetal FPGA software

This directory contains the C++ driver library, generated configuration files,
host-side scripts, and the ARM applications for running a quantized neural
network on the VTA accelerator in a Xilinx baremetal (no OS) environment.

## Directory layout


## Prerequisites

**Hardware / toolchain**

- Xilinx Vitis 2023.x – 2025.x (source `settings64.sh` before running Vitis scripts)
- A Vivado-exported XSA file for the target board

**Python (host scripts)**

The host scripts require Python ≥ 3.13 and `pyserial`.
A `uv`-managed virtual environment is provided:

```sh
cd src/fpga/software
uv sync          # creates .venv and installs pyserial
uv run host/uart_nn.py ...
```

## Deployment flows

Two axes are independent and can be combined freely:

| Axis            | Options                                            | Meaning                                              |
| --------------- | -------------------------------------------------- | ---------------------------------------------------- |
| **Runner**      | `run_nn`, `run_nn_uart`, `run_nn_debug`, `test_gemm` | Which ARM application is compiled                  |
| **Data loader** | `tcl`, `elf`                                       | How static model data (INSN/UOP/WGT/ACC) reaches DDR |

**Runner**

| Runner         | Input source                      | Behaviour                                              |
| -------------- | --------------------------------- | ------------------------------------------------------ |
| `run_nn`       | Pre-loaded in DDR (TCL or ELF)    | Runs inference once and exits                          |
| `run_nn_uart`  | Received over UART each iteration | Interactive loop driven by host                        |
| `run_nn_debug` | fsim golden inputs (ELF-embedded) | Per-layer VTA isolation check vs fsim golden outputs   |
| `test_gemm`    | Pre-loaded in DDR                 | Standalone GEMM correctness test                       |

`run_nn_debug` is a debug build (`NN_CHECK_LAYERS`): it requires the `elf`
loader and the `--emit-layer-check` artifacts. See
[Per-layer isolation check](#4c---per-layer-isolation-check-run_nn_debug).

**Data loader**

| Loader | Static model data                     | input_nn.bin                                    |
| ------ | ------------------------------------- | ----------------------------------------------- |
| `tcl`  | `load_nn_static.tcl` sourced in XSDB  | `load_input.tcl` (run_nn) or UART (run_nn_uart) |
| `elf`  | Embedded via `.incbin`; FSBL loads it | `load_input.tcl` (run_nn) or UART (run_nn_uart) |

## Full workflow

### 1 - Generate config files

After running the VTA compiler, pass its output directory to `gen_nn_baremetal.py`.
All files are written to `--outdir` (default: `gen/`) with fixed names.

```sh
python host/gen_nn_baremetal.py <compiler_output_dir> \
    --ddr-base    0x200000      \
    --max-addr    0x1ff00000    \
    --outdir      gen           \
```

| Flag                 | Default | Description                                                                                                     |
| -------------------- | ------- | --------------------------------------------------------------------------------------------------------------- |
| `--outdir DIR`       | `gen`   | Directory for all generated files                                                                               |
| `--ddr-base ADDR`    | `0x0`   | Physical DDR base; all buffer offsets are relative to this                                                      |
| `--max-addr ADDR`    | -       | Upper DDR limit; script exits with error if any allocation exceeds it                                           |
| `--config-json PATH` | -       | VTA hardware config JSON; reads `LOG_BLOCK`, `LOG_INP_WIDTH`, `LOG_OUT_WIDTH`, `LOG_WGT_WIDTH`, `LOG_ACC_WIDTH` |
| `--block-size N`     | `16`    | Override block size directly (takes priority over `--config-json`)                                              |
| `--emit-layer-check` | off     | Emit per-layer isolation-check artifacts (`nn_debug_map.h` + embedded golden in/out) for `run_nn_debug`. Requires `--ref-dir`. Off by default; normal images are unaffected. |
| `--ref-dir DIR`      | -       | Directory with fsim golden dumps (`--dump-layers`): `input<SUFFIX>.bin` / `output<SUFFIX>.bin`. Required with `--emit-layer-check`. |

The script warns on non-default configurations:

- **8-bit data width** (`LOG_INP_WIDTH` or `LOG_OUT_WIDTH` = 3): CPU ops use `int8_t`;
  ensure compiler output and network quantization match.
- **Asymmetric stride** (`sh ≠ sw`): the functional simulator's `im2row` only supports
  isotropic stride; simulation results will differ from FPGA execution.

**Generated files**

| File                 | Description                                                                                                                               |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `vta_hw_config.h`    | C++ type aliases (`vta_inp_t`, `vta_out_t`, `vta_acc_t`, `VTA_BLOCK_SIZE`) derived from the hardware config; required by `vta_cpu_ops.cc` |
| `nn_ddr_map.h`       | `LayerDesc nn_layers[]` - VCR register values and buffer addresses per VTA layer                                                          |
| `nn_exec_plan.h`     | `NnExecStep nn_exec_steps[]` - ordered VTA + CPU steps for the full model                                                                 |
| `nn_debug_map.h`     | _(only with `--emit-layer-check`)_ `DebugLayerDesc nn_debug[]` - per-layer golden input/output addresses + input destination buffer       |
| `load_nn_static.tcl` | XSDB: loads INSN/UOP/WGT/ACC only (no input)                                                                                              |
| `load_nn.tcl`        | XSDB: loads INSN/UOP/WGT/ACC + input_nn.bin                                                                                               |
| `load_input.tcl`     | XSDB: loads input_nn.bin only (companion for ELF loader or standalone)                                                                    |
| `nn_bin_data.S`      | AArch64 assembly with `.incbin` for each static buffer                                                                                    |
| `nn_vta_sections.ld` | Linker fragment placing each `.vta_lN_*` section at its DDR address                                                                       |

### 2 - Create the Vitis workspace

The script creates a platform from an XSA, builds the BSP, and creates an
application component with VTA driver linked in.
`--runner` and `--data-loader` allows to specify which applications to create.

**Create workspace and application for the first time:**

```sh
source /opt/Xilinx/2025.2/Vitis/settings64.sh

vitis -s host/create_vitis_workspace.py \
    --xsa         path/to/design.xsa  \
    --workspace   path/to/vitis_workspace    \
    --runner      run_nn_uart         \
    --data-loader tcl
```

**Add a new application to an existing workspace** (platform already built,
`--xsa` omitted):

```sh
vitis -s host/create_vitis_workspace.py \
    --workspace   path/to/vitis_workspace    \
    --runner      run_nn_uart         \
    --data-loader tcl                 \
    --app-name    my_app
```

**Create multiple app components in one call:**

```sh
vitis -s host/create_vitis_workspace.py \
    --xsa         path/to/design.xsa  \
    --workspace   build/vitis_proj    \
    --runner      run_nn run_nn_uart  \
    --data-loader elf tcl
```

| Flag                     | Default                               | Description                                                                               |
| ------------------------ | ------------------------------------- | ----------------------------------------------------------------------------------------- |
| `--xsa PATH`             | _(required for first run)_            | Vivado XSA file; omit to reuse an existing platform                                       |
| `--workspace PATH`       | `vitis_workspace`                     | Vitis workspace directory                                                                 |
| `--platform-name NAME`   | `vta_platform`                        | Name of the hardware platform component                                                   |
| `--runner`               | `run_nn`                              | One or more of `run_nn`, `run_nn_uart`, `run_nn_debug`, `test_gemm`; creates one app component per runner |
| `--data-loader tcl\|elf` | _(required for run_nn / run_nn_uart / run_nn_debug)_ | Selects which generated config files are copied into the app; not used for `test_gemm`. `run_nn_debug` requires `elf` (golden data is `.incbin`-embedded). |
| `--cpu NAME`             | `psu_cortexa53_0`                     | BSP processor instance name; check `xparameters.h` in your BSP for the correct value      |
| `--app-name NAME`        | `vta_<runner>_<loader>`               | Override the app component name (single runner only)                                      |
| `--baud N`               | `921600`                              | UART baud rate compiled into the firmware (`VTA_UART_BAUD`)                               |
| `--dry-run`              | -                                     | Print files that would be copied without calling Vitis APIs                               |

App component names are auto-derived: `vta_run_nn_tcl`, `vta_run_nn_uart_elf`,
`vta_test_gemm`, etc.

The script also patches Vitis generated files:

- for the `elf` data loader, it adds inside the application linker script:

```
INCLUDE nn_vta_sections.ld
```

- it includes the driver sources in the user cmake file as well as the \*.S assembly files required by the `elf`` flow

### 3 - Build and deploy

Build the application in Vitis, then load the ELF and static model data:

```sh
# In the Vitis XSDB console (or xsct shell):
connect
targets -set -filter {name =~ "psu_cortexa53_0"}
dow path/to/application.elf

# TCL data loader - load static model data:
source gen/load_nn_static.tcl

# run_nn only - also load the input:
source gen/load_input.tcl
```

For the `elf` data loader, static model data is already embedded in the ELF.
Only source `load_input.tcl` when using `run_nn` (not needed for `run_nn_uart`).

### 4a - One-shot inference (`run_nn`)

The ARM application runs the full inference pipeline once and exits, printing
per-step logs. Input must be pre-loaded before execution starts (via TCL or
ELF + `load_input.tcl`).

```
=== VTA NN runner: <N> step(s) ===
[vta] step 0/<N-1>: <name>
...
=== NN done ===
```

### 4b - UART interactive loop (`run_nn_uart`)

The ARM application boots, prints the input/output sizes, then loops: waits
for a trigger byte, receives input over UART, runs inference, and sends back
the output. Only static model data needs to be pre-loaded; `uart_nn.py`
handles the input/output exchange.

**Protocol**

```
Board → "=== VTA NN runner: <N> step(s) ===\r\n"   (once, at boot)
Loop:
  Host  → 0x01  (trigger byte)
  Board → "input=<N> out=<M>\r\n"
  Board → "READY\r\n"
  Host  → <input_n_bytes> raw HWC INT8 bytes
  Board   (runs inference, prints per-step logs)
  Board → "OUTPUT\r\n"
  Board → <out_n_bytes> raw bytes
```

**`uart_nn.py` - host client**

```sh
# Single run:
python host/uart_nn.py \
    --port /dev/ttyUSB0 \
    --input  input_nn.bin \
    --output out.bin

# Multiple inputs → results/:
python host/uart_nn.py \
    --port /dev/ttyUSB0 \
    --input img1.bin img2.bin \
    --output-dir results/

# Show per-layer step and cycle logs:
python host/uart_nn.py \
    --port /dev/ttyUSB0 \
    --input input_nn.bin --output out.bin \
    --verbose
```

| Flag                   | Default         | Description                                                       |
| ---------------------- | --------------- | ----------------------------------------------------------------- |
| `--port DEV`           | _(required)_    | Serial device (`/dev/ttyUSB0`, `COM3`, …)                         |
| `--baud N`             | `921600`        | Baud rate (must match `VTA_UART_BAUD` compiled into the firmware) |
| `--input FILE …`       | _(required)_    | Raw input file(s); one inference per file                         |
| `--output FILE`        | -               | Output file (single-run shorthand)                                |
| `--output-dir DIR`     | -               | Directory for per-run output files                                |
| `--repeat N`           | `1`             | Repeat each input N times                                         |
| `--input-bytes N`      | _(from banner)_ | Override input size (banner still consumed)                       |
| `--output-bytes N`     | _(from banner)_ | Override output size (banner still consumed)                      |
| `--banner-timeout SEC` | `20`            | Seconds to wait for banner after sending trigger                  |
| `--ready-timeout SEC`  | `60`            | Seconds to wait for `READY` before each run                       |
| `--verbose`            | -               | Print per-layer board logs during inference                       |
| `--detile`             | -               | Convert VTA block output to NCHW flat before saving               |
| `--output-shape C,H,W` | -               | Required with `--detile`; output tensor shape                     |
| `--block-size N`       | `16`            | VTA block size used for de-tiling                                 |

### 4c - Per-layer isolation check (`run_nn_debug`)

A debug build that pinpoints which VTA layer first produces wrong data on the
board. Instead of chaining layers (where one corrupt output cascades into all
later layers), it runs **each VTA layer in isolation on fsim-precomputed golden
inputs** and compares its raw output (pre-rescale) against the fsim golden
output. The first layer reporting a mismatch is the true source of corruption.

It reuses the unmodified `run_layer()`; `run_nn` / `run_layer` / `LayerDesc`
are untouched. The whole path is gated by the `NN_CHECK_LAYERS` compile
definition (set automatically for the `run_nn_debug` runner), so normal images
carry no reference data.

**1. Generate the golden dumps with the functional simulator:**

```sh
# from examples/ (or the functional_simulator dir)
make fsim_inference FSIM_FLAGS=--dump-layers
# → simulators_output/input<SUFFIX>.bin and output<SUFFIX>.bin per VTA layer
```

**2. Generate the board artifacts with the golden data embedded:**

```sh
python host/gen_nn_baremetal.py <compiler_output_dir> \
    --ddr-base    0x10000000                          \
    --config-json ../../../config/vta_config.json     \
    --emit-layer-check                                \
    --ref-dir     <repo>/simulators_output
```

The golden inputs/outputs are placed in a reserved DRAM region above all live
allocations, embedded as extra `.vta_lN_inref` / `.vta_lN_outref` `.incbin`
sections in `nn_bin_data.S`, placed by `nn_vta_sections.ld`, and described by
`nn_debug_map.h`. Layers whose dumps are missing are skipped (zero sizes).

**3. Create the app (elf loader, `NN_CHECK_LAYERS` set automatically):**

```sh
vitis -s host/create_vitis_workspace.py \
    --workspace   path/to/vitis_workspace \
    --runner      run_nn_debug            \
    --data-loader elf
```

**4. Build, `dow application.elf`, `con`, and read the UART.** Each layer prints
either `PASS` or `FAIL k/N mismatches` (with the first differing elements). The
earliest `FAIL` is the VTA-introduced corruption - fed golden inputs, so it is
not a cascade artifact.

> Note: this cannot be reproduced in simulation - fsim and the Verilated RTL
> match the golden references by construction. It is an on-board diagnostic.

## C++ driver library

The library has no dependencies beyond the Xilinx BSP (included by Vitis).

| Header          | Contents                                                                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vta.h`         | VCR register layout, `CTRL_LAUNCH` / `CTRL_DONE` bit definitions                                                                                                  |
| `vta_board.h`   | `board_init(baud)` - reinitializes the PS UART to the given baud rate at startup                                                                                  |
| `vta_ctrl.h`    | `launch()`, `poll_done()` - thin wrappers around VCR MMIO                                                                                                         |
| `vta_mem.h`     | `init_ddr_region()`, `dump_words()` - DDR init and debug helpers                                                                                                  |
| `vta_nn.h`      | `LayerDesc`, `run_layer()`, `run_nn()`                                                                                                                            |
| `vta_nn_debug.h`| `DebugLayerDesc`, `check_layer_output()`, `run_nn_debug()` - per-layer isolation checker; active only when built with `NN_CHECK_LAYERS` (no-op otherwise)         |
| `vta_cpu_ops.h` | `NnFormatInputStep`, `NnIm2RowStep`, `NnQaddStep`, `NnConcatStep`, `NnDequantStep`, `NnQuantStep`, `NnRescaleStep` and the corresponding `vta::run_*()` functions |

`board_init()` must be called at the very top of `main()`, before any
`xil_printf` / `inbyte` / `outbyte`. The BSP's pre-compiled `libxil.a`
boots the UART at 115200; `board_init()` reinitializes it to `VTA_UART_BAUD`
(default 921600) at runtime so no BSP rebuild is required. Both `run_nn.cc`
and `run_nn_uart.cc` call it as their first statement.

`run_layer()` handles the full hardware interaction for one layer: flush input
caches, program VCR registers, launch VTA, poll for completion, and invalidate
the output cache.
